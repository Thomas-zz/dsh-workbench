# 个人工作台：日计划、周目标与连续记录

日期：2026-11-12。状态：方案已进入实现。首版实现与验证范围见 `calendar-workbench-validation-20261112.md`；第二轮公共随手记、统一模型、轻量新增与整理记录的当前行为见 `workbench-round2-validation-20261112.md`，后者优先；下文保留原设计口径，超出验证范围的内容不表示已交付。

本轮修订：依据用户补充，采用自由编辑、直接生效、后台定时整理；取消默认排程确认和频繁校验提醒。Agent 是收集与排期助手，日常执行会话不承担维护工作台的额外步骤。

## 设计结论

把工作台的主入口改为「日 / 周 / 月」，以日计划安排执行，以周目标组织大项，以连续的每日记录支持回顾。任务放入某一天、某一周，就自动拥有对应的计划归属；截止期限只用于确实有交付约束的事项。

日计划的核心动作是「写一句、排个序、勾完成」。时间块是可选的进一步安排。每天未完的事项自动延续，同时保留昨天当时的状态。

默认由独立整理助手定时读取已产生的会话记录，补充任务、归并进展并安排日/周计划。用户打开工作台时已有可调整的安排，直接拖动即可。日常 agent 不必每轮登记、同步、询问或提醒，整理失败也不影响其正常执行。

## 依据与现状

- 阅读了个人日历笔记里若干天的记录。里面已有每日重点、按时间段划分的安排、历史未完事项、随手想法与完成勾选。相邻日期存在连续承接的事项。借鉴的是这种组织思想，不照搬模板、分类或旧内容。
- 个人笔记里的周记目录当前为空；周目标和月聚合的设计依据是本次用户描述，不声称旧文件已经实现这些组织方式。
- 现有 `src/ops.js` 的 todayView 和 `client/desk.js` 的 todaySections 用「进行中 ∪ 今天及以前到期 ∪ 焦点」组成今天，缺少独立的日/周计划归属。
- `client/views/today.jsx` 的捕获框区分灵感和任务，`client/desk.js` 默认选择灵感。截止时间在展开编辑器中填写。
- `src/tools.js` 只有 due、focus 等时间相关参数；`src/prompts.js` 的活状态提供计数，没有完整的日、周计划上下文。
- 现有任务已有来源会话、执行进展和关联验收结果，适合继续复用。`src/ops.js` 的 cleanup 会按保留期删除完成任务，未来必须先保留历史记录再清理。
- 本轮通过 ego-browser 进入 https://track.toggl.com/timer，实际查看了 Week view / 5 days view / Day view 选项，切换单日与整周、打开日期选择器、切换 Calendar / List view。可借鉴同一工作区内切换范围与展示方式、日期列和时间刻度。未成功验证空白格新增、已保存时间块拖动或拉伸，不把这些写成已验证的 Toggl 行为；本方案中的拖动与拉伸是自身设计。未新增或修改 Toggl 时间记录。
- 现有 `src/learn/scan/index.js` 已统一扫描 DSH、Codex、Claude、ZCode 的用户输入；可复用来源适配与增量读取基础，但用户输入本身不足以证明任务完成。任务整理需要另补可用的助手结果、完成事件和上下文证据，不直接复用知识问题筛选规则。

## 概念与时间规则

| 概念 | 用户理解 | 示例 |
| --- | --- | --- |
| 项目 | 长期归属，可选 | 工作台优化 |
| 周目标 | 这一周希望推进的大项 | 跑通日计划与顺延 |
| 日行动 | 今天实际要执行的一步 | 整理顺延边界，预计 45 分钟 |
| 随手记 | 还没决定要做的想法或资料 | 以后考虑手机快捷入口 |

关系通常是「项目 → 周目标 → 日行动」，但不强制逐层创建。临时事项可以直接进入某日，独立日行动不需要父目标。月视图聚合完整周，不额外增加一层月任务。

| 时间信息 | 产生方式 | 含义 |
| --- | --- | --- |
| 计划日期 | 在某日新增、拖入日期列、自然语言安排 | 准备哪天做，可自由移动 |
| 计划周 | 在周视图新增、关联周目标或由计划日确定 | 准备在哪周推进 |
| 预计时长 | 可不填；快捷选 15/30/60/90 分钟或自定义 | 排时间时占多大空间 |
| 时间位置 | 拖到时间轴，或按顺序预排 | 当天大致何时做 |
| 硬截止 | 用户明确说必须、最晚、提交期限等 | 对外承诺的期限，顺延不会改动 |

日行动的安排周由计划日期计算；所属周目标使用稳定 ID 关联，历史周归属保存在每周记录中。行动移到下一周不偷偷改父目标的期限，也不复制父目标。周视图会显示「此目标有行动安排在下周」，到周切换时再按规则承接目标。

「这周做一下」只进入本周，不自动编一个周五截止。「周五发布」可先记录周五计划；只有明确的约束才写入硬截止。缺少期限就保持空值，不为提高字段完整度制造逾期。

## 主界面与导航

工作区采用「计划 / 项目 / 随手记 / 待验收 / 学习」。计划内部切换「日 / 周 / 月」；原“全部”保留为项目中的筛选入口。待验收与想法分开，因为前者需要明确处理结果。

待验收是可选的结果入口，不是每件个人任务必须经过的一道流程。普通任务可以直接完成；只有明确需要用户判断的结果才留在这里，不在每个对话回合催处理。

主题沿用 DSH 明暗主题。用户在电脑前日常工作、频繁查看并调整计划，界面应以紧凑文字和清晰操作为主。当前日期、选中项和主要按钮用宿主强调色，项目色只作辅助识别。

### 日视图：默认入口

顶部：日期、前后切换、回到今天、日历选择、单日/3日/7日、清单/时间轴。

默认单日清单；宽屏允许展开为 3 日或 7 日。避免默认铺开整周空时间格，让用户每次打开都要找当前任务。侧栏窄屏保留单日，宽工作区才展示多列，列宽不足时横向滚动。

视图选择记住上次使用状态；选择时间轴或多列后，不在下次打开时强行切回单日清单。参考 Toggl，把日期范围与清单/日历作为同一页面的两个控制项。

```text
计划    日 · 周 · 月       ‹ 2026-11-12 周四 ›  今天
显示    单日 / 3日 / 7日    清单 / 时间轴

本周目标（可收起）        11/12 今天           11/13 周五
跑通日计划  2/5          今日重点             今日重点
整理学习入口 1/3         □ 顺延规则  45m       □ 拖动交互  60m
                        □ 数据模型  60m
                        其他安排             其他安排
                        □ 文案调整  30m       □ 验收用例  45m
                        ＋ 写一句，回车添加    ＋ 添加

                        等待 / 待验收         等待 / 待验收
                        已完成 2 项           已完成 0 项
                        今日记录……           今日记录……
```

左侧周目标是可收起的辅助区，不与当天行动争夺主空间。点击目标的「拆一步到今天」直接新增关联行动；拖动目标到某日时打开一行行动输入，不把整个周目标误当成一个小任务。

每个日期列包含：今日重点、其他安排、等待/待验收、已完成、自由记录。重点数量不设上限，也不提示“太多”；顺延项用轻量文字标记来源日期，仍参与正常排序，不另造一个越来越长的待办区。

输入默认创建当前日期的日行动，不要求先选“灵感/任务”。旁边提供「随手记」入口。历史日期也可直接补写、更正，无需先解锁或经过确认流程；程序保留更正轨迹，正常顺延仍不覆盖原记录。

### 自由使用原则

- 项目、父目标、估时、时间位置都可缺省；只写标题也能用。
- 新增、编辑、拖动、改期、完成直接保存，提供撤销，不弹通用确认框。
- 允许重叠时间、超出建议容量、周末安排、跨周移动、临时改变顺序。容量只是一行可折叠的参考数，不是限制。
- 允许直接勾完周目标，不要求所有子行动先完成；剩余行动继续保留，用户需要时再处理。
- 顺延、分类、估时与任务整理默默完成，默认只显示“上次整理时间”和一个可展开的变更摘要。
- 不自动弹“是否延期”“是否确认排期”“为何未完成”；只在确实无法保存时用就地提示说明，并保留输入。
- 去重、数据完整性和并发处理由后台承担，不转换成用户必须处理的一系列校验问题。

### 时间轴与预估

- 清单内上下拖动调整顺序；任务行直接选择预估时长，无需展开详情。
- 时间轴空白处点击或拖出一段范围，直接输入标题即可创建，落点自动带入日期与时间，框选高度带入时长；不打开完整任务表单。
- 时间轴上方是「未排时间」，未知时长可以一直保留，不阻止使用。
- 从未排时间拖到时间轴，未估时任务暂用可调整的 30 分钟块，并明确显示“暂估”。拖动块的位置改时间，拖动底部改本次计划时长。
- 提供「帮我排一下」，按已有可用时段、顺序和估时直接排好并支持撤销，不默认增加预览和确认步骤。示例时段为上午/下午，可一次配置，某天也可覆盖。
- 助手可依据任务内容补一个粗略估时，来源在详情中可查，用户随手改即可。内容不足以估算时留在未排区，不追问。无法装入当天的任务仍可见；没有明确当天要求的新任务可安排到本周后续空闲日。
- 普通拖动只移动所选块，允许时间重叠，采用并排或错位展示，不弹冲突警告。另提供「从这里往后重排」。跨日拖动默认保留顺序和时长，清空原日具体时间；明确落在目标时间格时采用落点。
- 顶部可显示“计划 6h / 可用 5h”，作为参考信息；超出时仍能任意添加和拖动，不自动告警或阻止保存。
- 预计时长代表用户需要投入的精力；agent 后台运行和等待部署等时长不自动占用个人工作容量。
- 没做完不按时钟推算剩余工作量。保留上次预估，用户或 agent 有依据时再调整。确实需要跨多日的较大行动，可拆成有意义的子行动。
- 所有拖动均有「移到明天/选日期/上移/下移」菜单或键盘替代，完成后可撤销。

不显示计时器、开始计时、倒计时、实际耗时或计费。

### 周视图：看大项与拆分

周视图的主列表是本周目标，显示简短结果描述、相关项目、已完成行动数、下一步及等待原因。展开目标可以看到关联行动及各自日期，也能直接拆分或安排到某日。

「周视图」和「日视图的 7 日多列」是两个不同尺度：前者用于决定本周推进什么，后者用于挪动每天具体做什么。二者可以互相跳转并保留筛选。

周目标的完成以结果达成为准，用户可以随时直接勾选。助手有明确完成证据时也可更新；没有证据时不会只因子项暂时都勾完就推断大目标已达成。这里是助手的判断原则，不是用户操作限制。

### 月视图：由周组成

按周展示横向区段，每周显示目标、已达成结果、延续事项和简短周记录；点击进入该周。月视图不铺开所有日行动，也不要求再维护月任务。

默认周一开始，显示明确日期范围。跨月周沿用同一个周 ID，可在相邻月份显示带范围标识的同一周，月统计按事件实际发生日归属，不能重复累计。

## 自动顺延与每日一版

### 关键原则

同一任务保持同一个 ID；日/周记录保存当时的安排与状态。顺延只改变未来的活动安排，不覆盖过去。

例如：11 月 12 日的「整理顺延规则」未完成，13 日自动承接。查看 12 日显示“当天未完成，延续至 13 日”；13 日完成后，12 日记录依然如此，并可另看“目前已完成”。完成统计只记 13 日一次。

### 日切换

1. 按工作台时区跨日生成当日记录，后台运行时自动处理；未运行则下次打开或 agent 访问时补做。
2. 承接仍安排在过去的未完行动，保留原相对顺序，默认放在新一天已有安排之后。新一天人工设定的重点和固定时间块优先保留，顺延项不自动升级重点。
3. 清空旧的具体开始时间，保留时长供重新排列；等待事项进入等待区，不占时间轴。
4. 已明确挪到未来日期、搁置、取消、已完成的任务不被拉回今天。已在今天有安排的同一任务不重复添加。
5. 默认顺延到下一个自然日，设置中可切换为下一个工作日；显式安排在周末的任务仍按原安排展示。硬截止独立显示，不受休息日和顺延影响。
6. 多天未打开时补齐必要日期记录和承接轨迹，空白记录标明自动生成，不伪造当天做过什么；当前活动安排只保留一份。

历史快照优先来自当日事件。没有历史事件依据的旧数据，不推测当时状态。对历史补记追加更正记录；正常浏览和后来的完成操作不会重写已结束日的状态。

### 周切换

未达成且未搁置的本周目标，承接到新一周；上周保留原结果和“延续至下一周”。已明确安排更远未来的目标不被拉回。子行动已完成的部分继续保留，不重置为待办。

同一任务可以被日记录和周记录引用，但只产生一个活动安排及一次完成事件。周目标顺延不把所有未安排子行动自动塞进周一；只有日计划中的未完行动按照日规则承接。

### 防止自动堆积

连续顺延多次仍正常承接，不因次数弹提醒。用户需要时可在任务菜单选择「拆小一点 / 放回本周未安排 / 暂时搁置」；助手可以在用户主动查看周回顾时给出建议。不自动删除、不强迫填写原因，也不把顺延次数做成惩罚排名。搁置事项在项目或未安排列表中可找回。

硬截止已过时以日期小标记如实展示，不阻止编辑、顺延或完成，不默认向日常会话推送催办。

## “灵感”和“任务”的调整

现有区分的本意是：确定要做的进入任务，题外想法先停靠。但捕获时要求用户分类，且默认灵感，增加了理解成本。

建议保留用途、改名并改变入口：

- 在日计划里写，默认就是当天要做的行动。
- 在周计划里写，默认就是本周要推进的目标。
- 「随手记」专门存还没决定要做的想法、资料、备注，之后可直接安排到某日/某周。
- 每日记录中的纯文字不会自动变成任务；用户明确安排时再转换。
- Agent 的自发建议标为建议，不自动混入用户承诺的任务。
- 旧灵感迁移到随手记，保留原文、来源与已有转任务关系，避免再次生成重复任务。

## Agent 的时间与周期识别

### 默认定时收集，独立整理

默认采用「已落盘记录 → 定时增量读取 → 独立助手理解和归并 → 更新日/周安排」流程。这里设计的是插件内部能力，本次不创建 Codex 自动化，也不启动实际定时任务。

建议先以每 30 分钟一次作为可调默认值，并提供「现在整理」按钮。没有新内容就跳过模型调用；跨日/跨周顺延是普通程序操作，不依赖模型。宿主未运行则在下次启动后补扫，扫描游标按数据源保存，不把“本轮失败”当作已处理。

一轮整理完成以下事情：

1. 读取自上次成功处理以来的新记录，保留来源会话、项目、消息时间及必要相邻上下文。
2. 提取明确待办，区分用户要做的事、助手建议和知识讨论；按已有任务及来源关联去重，不逐条把对话变成新任务。
3. 归并后续变更，例如“改到下周”“这项已经做完”“先不做了”；结合上下文更新已有事项，不重复登记。
4. 按消息发生时的日期解释“今天/明天/本周”，不是按定时器运行时的日期。跨午夜补扫尤其要避免误排一天。
5. 明确要求立即执行的事项归入当时日期；明确周期按原话安排；确定要做但时间不明确的事项，可由助手结合项目和本周空位安排。纯想法保留在随手记。
6. 补充粗略估时、关联周目标，为新任务和原本未安排的任务排期，直接写入工作台。
7. 保存简短变更摘要，例如“新增3项、更新2项，已安排到周五”。摘要留在工作台，不注入执行会话。

定时助手使用独立的后台执行上下文、独立配置与低优先级队列，不向正在工作的会话发送触发消息，不更改它的模型，不占用它的对话回合。如果宿主只能串行运行模型任务，整理延后等待空闲；不通过打断或排到执行任务前面实现“定时”。实际资源隔离能力需要实现时验证，不承诺零资源开销。

第一版可以复用已有扫描器的只读来源适配；需要明确哪些来源能读到完整结果。只有用户输入的来源可以收集任务与明确的用户状态更新，但不能据此自动断言执行成功。普通任务有足够完成依据即可更新，不要求统一经过人工验收；确需用户判断的结果留在可选待验收区。

### 移除日常会话的额外负担

- 去掉工作台现有系统提示中“新任务必须调用工具登记”“每个环节调用工具同步”“每轮收尾提醒待验收”等强制维护要求。
- 默认停止向日常会话注入工作台活计数和晨报触发卡，晨报保留在工作台内。已有完成事件监听可继续被动记录，不新增模型步骤。
- 手动输入、UI 操作即时保存；工具/CLI 保留为用户主动要求“记一下、查今天、帮我重排”时的快捷入口，不作为默认收集依赖。
- 定时整理读取记录不会续跑原会话，也不会以原会话身份发送新消息。整理轮次不能把自身的整理输出再次收成新任务。
- 失败在工作台设置或同步状态中可查看并后台重试，主任务继续正常运行。

### 排期与用户修改的关系

用户不需要批准助手每次排期。助手自动安排新任务，并根据已知时间要求和空位填入计划；用户拖动后立即以用户的位置为准。后续整理不重复移动这些任务，也不要求额外点“锁定”。用户主动说“重新安排今天”或点击重排时，助手可重新安排指定范围。

没有足够信息的事项可以先放在本周未排时间区域，不为每个模糊点打断用户。助手生成的估时、日期或项目关系可以随时改，来源与依据只在展开时显示。

### 共享时间语义

所有入口共享同一套安排服务，包括 UI、独立整理助手、主动调用的工具与外部 CLI。时间规则由程序落实，不仅依靠提示词。

为整理助手提供当前本地日期、时区、来源消息日期、周起止日期、相关任务 ID、已有日/周安排和用户手动修改信息。仅在主动从工作台发起操作时提供对应视图日期；不把这份上下文强塞给所有正在运行的 agent。

| 用户表达/操作 | 默认解释 |
| --- | --- |
| 在 11 月 13 日列写「整理方案」 | 安排到 2026-11-13，无硬截止 |
| 11 月 12 日说「明天整理方案」 | 安排到 2026-11-13，无硬截止 |
| 「这周把工作台优化一下」 | 2026-11-09 至 11-15 的周目标 |
| 「周五前必须提交」 | 硬截止 2026-11-13；计划安排与期限分别记录 |
| 「以后考虑手机端」 | 随手记，不凭空设置日期 |
| 正在要求 agent 实施某个事项 | 在下一轮定时整理中复用已有任务或归入消息发生日，不要求执行 agent 立即登记 |

日期解析优先采用明确指令，其次是对应操作的视图日期。后台整理不能因为用户正在查看历史页而误用历史日期。自然语言相对时间以原始消息发生的本地日期解释，直接操作以本次请求日期解释；解析结果可在工作台详情查看，不逐条弹确认。

无日期的明确待办，在某日/某周视图中继承该容器；来自普通会话的，由整理助手结合本周目标和可用时段安排，信息不足时放到本周未安排。模糊表达不编造硬截止，排期详情用绝对日期显示并支持快捷改期。

建议扩展现有工具：

- `workbench_add/update`：支持事项层级、父目标、项目、计划日/周、预计分钟、可选时间块、独立硬截止；沿用稳定 ID、来源会话和 progress。
- `workbench_query`：支持指定日、周、月、项目、未安排；返回计划归属、关联目标、来源与截至该日的历史状态。
- 安排操作支持移动、排序、拆分、顺延和撤销，带预期数据版本与幂等键。
- 整理助手从已有记录和被动事件获取进展；普通任务按证据更新完成，需要用户判断的才进入可选待验收，不给所有任务加审核流程。
- 用户手动调整后的顺序、日期、估时优先；助手安排直接生效、可撤销，不默认要求预览确认，也不每轮重新洗牌。

## 统计的口径

| 视角 | 展示 | 约束 |
| --- | --- | --- |
| 日 | 今日完成行动、剩余已估分钟、未估时数量、可用容量、每日记录 | 估时不称作实际投入 |
| 周 | 周目标达成数、各目标子行动完成数、完成结果、延续事项 | 周目标和子行动分开统计 |
| 项目 | 关联周目标、已达成里程碑、当前下一步、等待事项、近期进展 | 不用行动条数冒充工程完成百分比 |
| 月 | 各周推进与达成结果、按实际完成日汇总的行动数 | 跨月周不重复计数 |

默认用“本周达成 2/4 个目标”“该目标已完成 3/5 个行动”等可核对表达。没有明确总范围的项目不显示虚假的百分比。若展示比率，说明分母是当前范围，新增/撤回事项要可追溯。

普通行动完成按唯一任务 ID 去重；周目标达成单独计数；完成后重新打开再完成，不在累计任务数中重复计数，历史活动仍保留。迁移前缺失的历史不补造。

## 实现建议与迁移边界

维持当前本地优先路线，设计上需要区分：

1. 事项身份与关系：项目、目标/行动、状态、期限、来源、进展。
2. 周期安排：哪个日/周、排序、时间位置、预估与是否手动固定。
3. 日/周记录及事件：当时的标题和状态、安排、补充文字、完成、顺延与更正。

这些是逻辑数据，不预先要求新增三套服务或三张表。可在现有 state 中演进并按月归档历史；若采用 JSON 继续支持多个 Host/CLI 进程，必须加入跨进程写锁、版本校验与原子事务边界。现有 Store 的 Promise 队列只串行化本进程，mtime 重载和原子 rename 不足以防止两个进程读改写互相覆盖。

顺延应作为幂等的日期结算操作，与任务移动/完成串行提交。UI、工作台晨报和整理助手都读取同一套已结算视图，避免两套 today 逻辑漂移。只读查询正常返回前可调用统一结算服务，但浏览未来日期不能提前触发未来结算。版本冲突先由后台重读合并：保留用户改动，放弃过时的助手排期，不把内部冲突常规地抛给用户。

迁移一次完成、可回退：

- 备份旧 state，升级 schema，并保留任务 ID、来源、progress、checklist 和验收关系。
- 正在做/焦点事项初次归入当天；已有未来日期可作为迁移后的计划日期；其余进入未安排。
- 旧 due 无法区分计划和硬截止，默认用于计划安排，原值保存在迁移信息中；有明确来源证据的才恢复为硬截止。不要求用户逐条确认日期含义，后续可以自由更改。
- checklist 先保留，只有明确安排执行时再提升为有 ID 的行动，避免迁移时生成大量伪任务。
- 从启用日开始可靠记录日/周历史。旧完成记录保留已知时间，不伪造过去每日快照。
- 修改 cleanup：有历史引用的数据先归档，不直接删除导致过去的日/周页面和项目统计丢失。
- 产品文档需同步补齐计划模块的定位；现有 PRODUCT.md 主要描述学习功能，不能直接当作完整工作台范围。

## 交付顺序与验收

第一阶段先闭环日常使用：日/周计划、自然归属、行内估时、拖动排序与跨日移动、3/7 日列、自动日/周顺延、稳定历史、随手记，以及独立定时收集、归并和日/周排期。同步去掉执行会话内的强制维护与催办。包含月度按周聚合和基础完成统计，让用户要求的三个尺度都能使用。

第二阶段补足精细安排：可切换时间轴、空白区域新增、时段设置、拖动块长度、直接自动排时段、可折叠容量参考、更完整的项目进展与月度回顾。基础估时和拖动排序在第一阶段已有，第二阶段解决具体几点做。

两阶段都属于本方案范围；阶段划分是实现依赖顺序。此次不实现计时、倒计时、计费、复杂循环规则或外部日历双向同步。

关键验收场景：

- 在某日输入一句话，无需日期表单便能被 UI 和 agent 查为该日任务。
- 说“本周推进”不会产生虚构周五截止；说“最晚周五交”会保留真实期限。
- 未完成事项跨日/跨周自动承接，刷新、重启或并发访问均不重复；旧记录不被后来完成覆盖。
- 多日未打开能够补齐轨迹，已明确改到未来的任务不会被拉回今天。
- 周目标和日行动跨周时关系连续，子行动不重置、完成统计不重复。
- 拖动改期、排序、用户修改和后台整理之间不丢数据；后台合并保留用户选择，撤销不覆盖后续新修改。
- 定时读取只处理新增记录，无新内容不调用模型；失败后可重试且不重复建任务，跨午夜的“明天”按消息发生日解析。
- 执行会话持续跑任务时，没有被注入登记要求、整理触发卡或验收催办；后台资源不足时整理延后，原任务不被抢占。
- 不填项目/父目标/估时也能添加；时间重叠、超容量、跨周改期、直接完成均可保存，不出现常规确认弹窗。
- 估时缺失、容量不足、任务等待、跨月周、日期跨年、补记历史、空视图、保存失败都有可理解表现。
- 键盘/菜单能完成拖动等价操作；窄侧栏可用，宽屏多列可滚动；主题跟随宿主。

空白日提示“写一句今天要做的事，或从本周目标拆一步”；空白周提示“写下这周想推进的一件大事”。保存失败保留输入并提示重试，不清空内容或假装已保存。
